Перед продолжением прогнать `ci/run_checks.sh all` и собрать review-пакет.

## Что уже лежит в ветке
- `3d-shooter/core/HandlePool.gd` — общая выдача слотов с handle по поколениям
  (`generation · 65536 + index`, int64), стек свободных индексов, Zero-Trust `set_state`.
- `3d-shooter/combat/StatBlock.gd` — переведён на HandlePool (публичный API и ключи снимка прежние).
- `3d-shooter/effects/AttackContextPool.gd` — первая версия пула контекстов атак.

## Обязательные правки (решение координатора)
1. **HandlePool и StatBlock.** Приёмка жёсткая: тесты и golden StatBlock проходят без единой
   правки; формат handle и ключи снимка не меняются; средний логический тик в `regress.gd`
   растёт не больше чем на 5% (3 прогона до и 3 после, цифры в пакет). Не уложился — StatBlock
   остаётся с inline-проверкой, HandlePool только в AttackContextPool. Показать, что
   Zero-Trust-проверки перенесены целиком.
2. **HITS_PER_CONTEXT = 64** (не 16): AREA-атака в толпе из 40 врагов. `hit_set_overflows` и
   `capacity_refusals` — ошибка конфигурации: `push_error` один раз, в doc-комментарии
   «корректность только при нулевых счётчиках», TODO на шаг 8 (regress и интеграционный
   тест падают при ненулевых).
3. **Освобождение дерева за O(размера дерева)**, не O(ёмкости): интрузивный список
   `PackedInt32Array next_in_tree`, `open_child` вставляет узел в список корня.
4. **Краевые случаи в контракте и тестах:**
   - повторный `close()` отказывает и не уменьшает `open_count` второй раз;
   - `close`/`try_register_hit`/`open_child` по устаревшему handle отказывают;
   - `open_child` от закрытого родителя разрешён, пока дерево живо (отложенные эффекты),
     и запрещён после освобождения дерева;
   - цели хранятся полным handle (с поколением): переиспользованный слот врага — другая цель (тест).
5. **Golden цепной молнии** из Python-модели, со сценариями отказов по глубине, бюджету и
   повторной цели.
